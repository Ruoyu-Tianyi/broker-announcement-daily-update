# 券商公告日更

把两份邮件附件中的新增公告插入专属工作区的活动总表，并在用户补充 PDF 后，将董事会决议内容写回新增区域。整个任务分成两个阶段；阶段一完成后必须暂停，不能自行跳过 PDF 交接点。每个完整批次验收通过后，最终文件成为下一批次唯一的活动总表。

## 首次使用引导

若尚无可识别的 `workspace.json`，在创建目录或处理附件前，必须完整阅读并执行 [首次使用介绍与初始化交互](references/first-use.md)：先用面向普通办公使用者的语言说明用途、日常操作、文件要求、安全边界和归档方式，再请求用户确认专属工作区根目录与初始总表。介绍只在首次初始化时完整展示；工作区已初始化后不要重复长篇介绍，只报告当前工作区状态并请求当日文件。

“安装 Skill”本身不等于已初始化业务工作区。不得因为 Skill 文件已解压就自动选择目录、移动总表或处理工作区内的旧附件。

## 不可突破的边界

- 只新增，不删除、改写或重新格式化任何历史内容。每次先在批次输出目录生成并验证新文件；只有完整批次通过验收后，才在先归档旧总表的前提下安全更新活动总表。
- 只使用附件和用户提供的公告 PDF 中的内容。不得根据标题、常识、其他公司公告或网络摘要编造、补齐或推断决议。
- 仅编辑本次新插入的行。行插入导致历史区域整体下移是允许的，但其值、公式、格式、批注、超链接和合并关系必须保持一致。
- 邮件下载不属于本流程。每天的两份新增 Excel 和后续公告 PDF 均由用户在当次对话中上传或明确点名，再复制进该批次的 `input` 归档。不要因此扩大权限或尝试登录邮箱。
- 不得自动使用工作区中残留的旧 Excel 或 PDF 充当当日输入。除总表外，只有用户在当前任务中明确上传或点名的文件才可作为来源。
- 若工作簿工具无法可靠保留现有 Excel 特性、合并单元格或单元格内局部富文本，停止并说明限制，不得用整格加粗或拆分单元格代替。
- 禁止控制用户电脑上的 Excel、文件管理器、浏览器或其他桌面界面，也禁止依赖用户当前打开的窗口、登录状态或本机 Office 安装。所有处理必须通过 Agent 可调用的文件级工具或随 Skill 提供的可审计脚本完成。

## 专属工作区与活动总表

执行任何日更前，完整阅读 [专属工作区与总表生命周期](references/workspace-layout.md)。

- 初次调用若没有 `workspace.json`，先请求用户确认专属工作区根目录和初始总表；确认前只做只读检查，不自行创建或采用任意目录。
- 初始化后固定使用 `master/【日更】券商公告.xlsx` 作为唯一活动总表。不得根据修改时间或文件名相似度从 `output`、`archive` 或旧目录中另选总表。
- 两份 Excel、后续 PDF、阶段一文件、最终文件和验证报告均按业务日期及 `run-NNN` 批次归档。PDF 上传较晚时仍归入原 Excel 批次。
- 归档文件只用于审计；不得自动把历史 `input` 中的文件当作今天的来源。完全相同的来源文件对已处理时停止，防止重复插入。
- 有待补 PDF、未解决项目或任何校验失败时，不更新活动总表。完整批次通过后，先归档旧总表，再以已验证的最终文件原子替换活动总表；不得先覆盖后备份。

## 输入与工具

阶段一需要：已初始化工作区中的活动总表，以及用户在当前对话上传的昨晚、今早两份 Excel。先用 `scripts/workspace_manager.py start-run` 建立日期批次并归档两份来源，再从归档副本处理。阶段二另需用户在阶段一清单产生后上传的、与每项董事会决议对应的公告 PDF；先用 `attach-pdf` 归入同一批次。

若当前对话尚未收到两份新增 Excel，只确认总表可用并请用户上传，不得从工作区寻找旧附件替代。阶段一完成后，只接受用户随后上传或明确指定的 PDF；更早任务遗留的 PDF 默认无效。

按能力而不是按产品名称选择工具。电子表格工具必须能以文件方式读取、整行插入、复制样式、维护合并区域、写入单元格富文本并导出 `.xlsx`；PDF 工具必须能从用户提供的文件中抽取文本并核对页面。不要转换成 CSV 后再写回总表，因为 CSV 会丢失格式、合并和富文本。

执行前先做能力检查。若当前 Agent 的文件级工具缺少上述任一必要能力，只能完成只读预检、报告行数和待解决能力，随后停止；不得切换为桌面操控，也不得用搬移数千行单元格模拟整行插入。

若环境具备 Python 3 和 openpyxl 3.1.5 或更高版本，完整阅读并优先使用 [文件级工作簿引擎](references/file-engine.md)。先运行自检和预检，禁止跳过阻止项。

## 阶段一：合并每日公告

执行前完整阅读 [工作簿操作与验收](references/workbook-workflow.md)。

1. 从 `workspace.json` 定位唯一活动总表；从当前批次 `run.json` 定位本次归档的两份来源文件及输出目录。若文件角色无法唯一确定，停止并询问；不得猜测或启用旧附件。
2. 读取两份来源表，排除标题行、表头、空行和合计行，分别报告有效公告行数。保留来源文件内的行序；两份文件的先后顺序按总表现有日更区惯例判断，无法判断时询问。
3. 找到总表最新一个完整日更区的两行表头，以及其正上方用于分隔日更区的空白行。插入行数必须为 `2 + 来源一有效行数 + 来源二有效行数`；若现有版式有分隔行，在该空白行插入，使原空白行和历史区整体下移并继续充当新旧日更区的分隔。没有分隔行时才在既有表头首行插入。
4. 将既有日更区的两行表头复制到新区域前两行。按表头名称和语义映射字段，不要只按列序号盲贴；映射不唯一、缺列或同名列含义冲突时停止。
5. 只在新区域写入两份来源表的公告。依据紧邻的既有日更区复制其格式规则，并仅在新区域合并连续相同日期和连续相同券商名称的单元格。
6. 扫描新区域的公告标题/内容列。仅将明确属于“董事会决议公告”的标题行加粗；不得把监事会、股东大会或仅提及董事会的其他公告误判为待补决议。阶段一单元格只有一行标题时可以整格加粗；阶段二添加正文后必须改为仅标题文本段加粗。
7. 将阶段一工作簿和报告写入当前批次 `output` 目录，执行历史区不变校验和可视化检查。不得直接写入 `master`。
8. 在对话中先输出去重后的待补券商名称列表，再输出逐公告明细。每项明细至少包含：券商名称、公告标题、公告日期、新工作簿中的工作表与单元格；同一券商多份公告不得合并成一个模糊项目。随后明确请用户上传对应 PDF，并暂停。

如果没有待补项，说明“本次新增公告中未发现明确的董事会决议公告”。阶段一文件通过最终验收后，运行工作区晋升流程更新活动总表，无需进入阶段二。

## 阶段二：补录董事会决议

收到 PDF 后，执行前完整阅读 [PDF 决议提炼与写回](references/resolution-extraction.md)。

1. 按券商名称、公告标题、日期及届次/会议次数，将每份 PDF 与阶段一清单逐项匹配。存在一对多、多对一或信息冲突时停止，仅报告未能匹配的项目。
2. 阅读每份匹配 PDF 的全部相关页，从正式决议段落提取实际审议通过的事项。保留原意、专有名词和条件，不补写 PDF 未载明的信息。
3. 在对应新单元格中写成：首行为原公告标题，后续为 `1、...`、`2、...`、`3、...`，每条独占一行。仅首行加粗，补充的决议内容不加粗。
4. 只调整本次新增行的自动换行和必要行高，保持列宽及历史行高不变。把最终工作簿和报告写入当前批次 `output` 并再次完成验收；全部清单项解决后，运行 `workspace_manager.py promote` 归档旧总表并更新活动总表。

## 异常处理

- 加密、损坏、宏/外部链接/特殊对象可能无法无损保留：先报告风险，未经用户确认不要降级转换。
- PDF 无文本层、页面缺失、内容模糊或决议措辞无法确认：该项保持未补录，并说明需要清晰/完整 PDF。
- 同一议案出现“未通过”“暂缓审议”“回避表决”等情况时，严格按 PDF 表述；不要把它写成“审议通过”。
- 任何校验失败都不得交付为完成状态。保留原文件和已生成的中间文件，报告具体差异与受影响位置。

## 最终交付

交付当前批次最终 `.xlsx`，并简要报告：业务日期和批次号、两份来源有效行数、共新增多少行、待补/已补决议项目数、未解决项目、输入归档目录、输出归档目录、旧总表备份和当前活动总表。不要宣称已从巨潮资讯网核验，除非确实访问并核对了对应原始公告。
