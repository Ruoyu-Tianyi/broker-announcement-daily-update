# 首次使用介绍与初始化交互

本规范只在尚未建立专属工作区时使用。目标是让不熟悉 Agent、脚本或目录结构的办公使用者，在第一次操作前明确知道要提供什么、Skill 会做什么以及哪些内容绝不会被改动。

## 1. 判断是否为首次使用

先对用户指定或当前已知的工作区做只读检查：

- 找到有效 `workspace.json`，且其中的活动总表存在：视为已初始化，不重复完整介绍。简要说明已找到活动总表，并请求上传或明确指定当日两份 Excel。
- 未找到 `workspace.json`：视为首次使用，发送下方介绍，然后等待用户确认工作区根目录和初始总表。
- 找到 `workspace.json`，但配置损坏、目录不完整或活动总表缺失：不要覆盖、重建或另选总表。说明具体问题并停止，等待用户决定修复方式。

不要把 Skill 安装目录、当前目录、下载目录或附件所在目录静默用作业务工作区。

## 2. 必须向使用者说明的内容

首次介绍必须覆盖以下信息，措辞可以适应对话，但不得遗漏实质：

1. **用途**：把每天两份券商公告 Excel 新增到长期维护的总表；遇到董事会决议公告时，先列清单，待用户上传原始 PDF 后再提炼并写回。
2. **首次需要**：一个专属工作区根目录，以及一份初始【日更】券商公告总表。初始化会复制总表，不移动或删除用户原文件。
3. **日常需要**：每次由用户在当前对话上传或明确指定昨晚、今早两份 Excel；阶段一列出待补项后，再上传对应公告 PDF。不要要求用户提前上传不在清单中的 PDF。
4. **两阶段交接**：阶段一只合并 Excel、识别并加粗董事会决议公告标题，然后暂停；阶段二严格依据上传 PDF 补录决议内容。
5. **文件管理**：输入、阶段输出、最终输出和旧总表备份按业务日期及批次归档；每次验收通过的最终文件才成为下一次使用的活动总表。
6. **安全边界**：只新增本批内容，不删除或编辑历史内容；不登录邮箱，不控制用户桌面或 Excel，不从旧归档擅自取附件，不根据标题、网络摘要或常识编造决议。
7. **环境要求**：Agent 必须能读取和写入 `.xlsx`、保留合并与富文本，并能读取用户提供的 PDF。能力检查不通过时只报告问题，不降级破坏格式。

## 3. 默认首次介绍文案

除非用户已经明确了解并要求跳过说明，首次调用应发送一段与以下内容等义的介绍：

> 你好，我会协助完成“券商公告日更”。首次使用需要先建立一个专属工作区，并复制一份初始【日更】券商公告总表作为以后持续更新的活动总表；您的原始总表不会被移动或删除。
>
> 日常操作分两步：先在当前对话上传或指定昨晚、今早两份 Excel，我会把新增公告插入总表，只修改本次新增区域，并列出需要补充董事会决议的券商和公告；随后您再上传清单对应的原始 PDF，我会严格依据 PDF 提炼决议并写回。全部校验通过后，最终文件才会成为下一次更新的总表。
>
> 工作区会按业务日期和批次保存输入、阶段输出、最终输出及旧总表备份。我不会登录邮箱、操控您的电脑或 Excel，也不会读取旧归档来冒充当日附件；不会删除、改写历史内容，更不会编造公告或决议。
>
> 请确认专属工作区根目录，并上传或明确指定初始【日更】券商公告总表。我完成只读检查后再初始化。

如果用户已经在同一条消息中明确给出了工作区根目录和初始总表，可先发送精简版介绍，再直接进行只读检查和初始化，不必重复询问已提供的信息。

## 4. 初始化后的首次回执

初始化成功后，简要告知：

- 专属工作区根目录；
- 活动总表路径；
- 初始总表只被复制，原文件未移动或删除；
- 下一步是上传或明确指定当日两份 Excel；
- PDF 应等待阶段一清单后再上传。

不得把“目录创建成功”误报为“日更已完成”。
