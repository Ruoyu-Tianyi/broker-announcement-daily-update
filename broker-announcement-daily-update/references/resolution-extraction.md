# PDF 决议提炼与写回

## 1. PDF 匹配

先建立一对一映射表，字段包括 PDF 文件名、券商名称、公告日期、公告标题、届次/会议次数、目标工作表和目标单元格。

- PDF 必须由用户在本次阶段一清单产生后上传，或由用户在当前任务中明确点名。不要自动采用工作区或更早对话遗留的 PDF。
- 优先使用 PDF 首页标题及正文中的公司全称，不只依赖文件名。
- 券商简称与公司全称的对应关系必须能从总表或 PDF 本身确认。
- 标题相近但届次、会议次数或日期不一致时视为冲突。
- 一份 PDF 同时包含多个公告，或一项清单对应多份 PDF 时，先说明对应关系并停止有歧义的写回。

## 2. 阅读范围与证据

先抽取文本以定位“审议通过”“会议审议”“表决结果”“议案”等段落，再检查相关页的视觉版面。阅读首页、议案/决议正文、跨页续文和附件引用，避免只读取搜索命中的一页。

只提取该次董事会实际形成的决议事项。通常以正式议案标题或“审议通过……”后的事项为准：

- 保留《关于……的议案》等正式名称，以及影响事项含义的限定词、子项和适用期间。
- 句式跟随该公告原文和用户提供的版式范例，不机械统一前缀：原文写“审议通过了……”时保留该句式；原文以正式事项标题列示时，可直接保留事项标题。不得为了风格统一增删“公司”“议案”“修订”等有含义的词。
- 可省略表决票数、签字页、备查文件、公告套话和与议案内容无关的背景说明，除非它们决定该事项是否通过。
- 对“通过”“未通过”“暂缓审议”“撤回”“关联董事回避”等结果必须如实区分。
- 若 PDF 只说“详见附件”而附件缺失，不得根据标题推测附件内容；将该项标为资料不完整。
- PDF 自身编号有跳号或重复时，保留事项顺序，但写回编号统一从 `1、` 连续编号；在交付说明中提示原文编号异常。

提炼是压缩表述，不是创造新结论。无法在 PDF 中指出明确依据的内容不得写入。

## 3. 写回格式

目标单元格使用换行分隔：

```text
原公告标题
1、第一项决议内容
2、第二项决议内容
3、第三项决议内容
```

- 标题必须与阶段一单元格原文一致，不擅自改名。
- 决议行采用中文顿号 `、`，每行只放一项。议案包含不可分割的子事项时，可在同一编号下保留原有分项标识。
- 只对第一行标题应用粗体；换行符及所有决议行保持非粗体。若单元格原来含其他正文，先确认其归属，不能覆盖。
- 开启自动换行，并只增大该新增行的行高到文字可见；不改列宽，不改历史行。

## 4. 不完整与冲突的表达

对不能安全写回的项目保持原单元格不变，并在对话中按以下字段报告：券商、公告标题、PDF、问题、需要用户补充的材料。不要在工作簿里写“待确认”“可能是”或占位推测。

## 5. 完成核对

- 清单项数 = 已补项数 + 未解决项数。
- 每个已补项都有唯一 PDF 证据与唯一目标单元格。
- 决议条数和顺序与 PDF 一致，所有否决/暂缓/回避情况准确表达。
- 标题文本未变且仅首行加粗；决议行全部不加粗。
- 完成 [工作簿操作与验收](workbook-workflow.md) 中的历史区与新区域验收。
