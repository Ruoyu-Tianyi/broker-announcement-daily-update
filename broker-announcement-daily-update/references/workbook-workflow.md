# 工作簿操作与验收

本文件用于阶段一，也用于阶段二写回后的最终校验。

## 1. 预检与只读基线

在任何编辑前：

1. 检查当前 Agent 的文件级工作簿能力。必须支持真实整行插入、样式复制、合并区域维护、富文本写入和 `.xlsx` 导出；不满足时只做预检并停止。不得启动、聚焦或操作用户桌面应用，也不得使用 GUI 自动化、Office COM 或远程桌面作为后备方案。
2. 只使用 `workspace.json` 指向的 `master/【日更】券商公告.xlsx`；两份来源 Excel 必须先由当前对话上传或明确点名，再归档进当前批次并由 `run.json` 定位。记录文件角色及来源，不按修改时间挑选，也不启用工作区旧附件。
3. 记录总表文件名、工作表名、已用区域、隐藏行列/工作表、冻结窗格、筛选、表格对象、命名区域、条件格式、批注、超链接、公式、合并区域以及是否含宏或外部链接。
4. 以文件级渲染或工作簿检查功能观察最近两个既有日更区，确认日更区的边界、两行表头、区块间空白分隔行、数据顺序、日期与券商合并规则、字体、字号、边框、填充、对齐、自动换行、行高和列宽。
5. 为插入点以下历史区域建立基线。至少保存每个单元格的值/公式、数据类型、样式标识、批注和超链接，以及合并区域清单。若工具支持，还要记录条件格式、数据验证和对象锚点。
6. 不在活动总表上试做。所有阶段文件先写入当前批次独立输出目录。上传文件复制进专属工作区的日期输入目录用于审计，但不复制进 Skill 目录，也不把历史归档登记为未来任务的默认来源。

无法唯一识别“最新既有日更区”时，列出候选工作表和行号并询问。不要以“第一张表”“第一个日期”或文件修改时间代替版式判断。

## 2. 来源表行数与字段映射

- 有效公告行是包含实际公告记录的行；不计文件标题、表头、全空行、说明行和合计行。
- 分别记录两份来源表的有效行数 `n1`、`n2`，并检查是否存在空白关键字段、完全重复记录或疑似重复记录。只报告重复，不擅自去重，除非总表既有规则明确要求且用户同意。
- 规范化表头时只可做不改变含义的处理，例如去除首尾空格和换行。通过表头名称、示例值及总表惯例共同确认映射。
- 来源列无法映射时不得丢弃；先报告来源列名和示例值。总表列没有来源值时保持空白，不自行填默认值。

## 3. 插入与复制

设最新完整既有日更区的首行表头为 `header`，插入行数为 `k=2+n1+n2`：

- 若 `header-1` 是该区块的空白分隔行，则令 `insert_at=header-1`，在 `insert_at` 插入 `k` 行。原空白分隔行移到 `insert_at+k`，原表头移到 `header+k`。
- 若既有版式明确没有空白分隔行，则令 `insert_at=header`。不要自行增加版式中不存在的分隔行。
- 若表头上方有多行空白，选择紧邻表头的最后一行作为分隔行；如果这些空白行用途不明，停止并询问。

插入完成后：

- 新区域 `insert_at:insert_at+1` 是从随历史区下移后的两行既有表头复制而来。
- 表题行须保留与范例一致的横向合并和居中方式；本任务中“券商公告”应横跨日期、券商名称和公告题目三列，不能只把文字复制到左侧单元格。
- 数据区严格包含 `n1+n2` 行，不夹空行，不覆盖新区域之外的单元格。
- 内容写入顺序应匹配既有日更区惯例。若惯例为日期降序，则两份来源按对应日期排列；同日内部保持来源顺序。无法确定时暂停询问。
- 从既有日更区中选择语义对应的模板行复制格式。不要用整表格式刷，不要自动套用新主题，也不要改变全表列宽。
- 新增日期按用户确认的范例显示为 `yyyy/m/d`（例如 `2026/8/27`）；只设置新增日期区域的数字格式，不改变历史日期格式。
- 复制表头与数据格式时涵盖字体、填充、边框、对齐、数字格式、自动换行和行高；公式只在既有模式明确要求新行延展时复制，并核对相对引用。

## 4. 合并单元格

- 只合并新数据区内连续且完全相同的日期值；每个合并区域的左上角保留该日期。
- 对券商名称采用相同规则：只合并连续、完全相同且按既有版式应合并的记录。
- 不跨越两个日期组、空行或来源顺序造成的不连续记录合并，也不触碰历史区合并。
- 合并前确认组内除左上角外没有不同值，避免合并导致数据丢失。

## 5. 董事会决议识别与首行加粗

优先依据公告标题。下列属于高置信度信号：

- 标题明确为“董事会决议公告”；
- 标题包含届次和会议次数，并明确写有“董事会……会议决议公告”；
- 标题虽略有排版差异，但语义明确是某次董事会会议的决议公告。

仅出现“董事会”“经董事会批准”“董事会秘书”“董事会换届”等字样，不足以认定为决议公告。监事会决议、股东大会决议也不进入清单。

阶段一只有单行标题且尚无正文时，可以将整格设为粗体，因为此时整格即标题。若单元格还含其他来源文本，只对确认的标题行加粗。阶段二加入决议内容后，必须使用单元格内富文本将标题文本段设为粗体，并将所有决议行设为非粗体；不能让新增正文继承整格粗体。

## 6. 历史区不变校验

插入行数为 `k=2+n1+n2`。校验编辑前 `insert_at` 及以下的历史内容，与编辑后 `insert_at+k` 及以下的内容一一对应：

- 值、公式、数据类型、批注、超链接一致；
- 字体、字号、粗体、颜色、填充、边框、对齐、数字格式和保护属性一致；
- 每个历史合并区域仅整体下移 `k` 行，范围形状不变；
- 历史区的条件格式、数据验证、筛选、隐藏状态和对象没有丢失或越界；
- 新区域之外不存在无解释的差异。

结构性插行可能让公式引用按 Excel 规则更新。若公式文本发生变化，必须确认它只是保持相同逻辑引用所需的结构性变化，并在交付说明中列出；否则视为校验失败。

## 7. 新区域验收

- `写入公告数 = n1+n2`，并与两份来源逐行核对关键字段。
- 新增总行数严格为 `2+n1+n2`。
- 两行表头内容和样式与既有日更区一致。
- 日期及券商合并范围正确，无不同值被吞并。
- 待补清单中的每项都能定位到唯一单元格。
- 阶段二后，每个已补单元格均为“标题 + 换行 + 编号决议”，且只有标题行加粗。
- 扫描受影响工作表的公式错误，并渲染查看新区域与上下边界；检查截断、异常行高、边框断裂、错位合并和不可读文字。

只有全部通过时才能将文件标记为完成。

## 8. 总表的持续使用

- 阶段一和阶段二均先生成独立输出，不直接覆盖工作区总表。
- 专属工作区初始化即确认了“完整批次验收通过后更新活动总表”的长期规则，因此正常日更无需每天重复询问是否采用。
- 有待补 PDF 时不得用阶段一文件更新总表；没有待补项，或阶段二全部清单项已解决且最终验收通过时，才执行晋升。
- 晋升前核对活动总表仍是本批次开始时的同一哈希；随后先把旧总表复制进日期/批次备份目录，再原子替换活动总表，并核对新总表与最终输出哈希一致。
- 如果活动总表在批次处理中被人工或其他任务改动，停止晋升并报告冲突，不得覆盖对方修改。
- 不因整理工作区而删除旧附件或总表；删除属于单独的破坏性操作，必须由用户明确指定目标。
